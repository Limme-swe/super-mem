# Search indexing

super-mem always provides local exact, structured, and lexical retrieval. Optional document expansions and dense vectors can add semantic candidates, but they are generated by a caller-owned background worker. The core does not choose, download, or invoke a model during memory writes or recall.

## Default search path

Every non-retracted current memory has a rebuildable, contentless FTS5 row. Its canonical fields are the title, body, tags, entities, and artifact paths and symbols. A separate alias field is derived deterministically from the same data:

- Camel case, snake case, kebab case, `::`, path separators, and letter/digit boundaries are split into searchable components.
- Compound spellings are indexed in compact form.
- A small coding and error lexicon adds conservative alternatives such as common operating-system error names and their plain-language forms. An alias is added only when its trigger is present.
- Terms are normalized, deduplicated, emitted in a stable priority and sort order, and bounded to 512 terms and 8 KiB. Given the same memory revision and alias algorithm version, the output is stable.

Recall uses distinct FTS channels rather than turning every query into one broad match:

| Channel | Match |
| --- | --- |
| Exact | Literal title or body substring, with FTS used as an index when possible. |
| Strict lexical | Up to eight safe query terms joined with `AND` across canonical fields. |
| Loose lexical | Up to 24 safe query terms joined with `OR` across canonical fields. |
| Strict code alias | The bounded all-term query against deterministic aliases only. |
| Code alias | The loose query against deterministic aliases only. |
| Semantic expansion | The loose query against registered background expansions only. |

Exact diagnostics, artifacts, tags, entities, recent records, and an optional dense-vector channel contribute additional candidate lists. Namespace, workspace, repository, lifecycle, kind, and time predicates run before per-channel limits. Weighted reciprocal-rank fusion, Git applicability, importance, confidence, trust, feedback, and diversity selection then produce a deterministic final order. Generated aliases, expansions, and vectors select candidates; only the canonical memory is rendered as untrusted evidence.

The default path needs only the release binary and SQLite. It has no network dependency, model runtime, platform-specific vector library, or first-run model download. The portable float and random-hyperplane representation is the same on the supported Linux, Windows, and macOS release targets.

## Background projection workflow

A search profile identifies one immutable generator configuration. `model_digest` should cover the model or expansion rules, tokenizer, preprocessing, vector dimensions, and similarity convention. super-mem records this value but does not verify an external model installation. Reuse the same profile only for byte-for-byte compatible generation. Dense queries can select a new profile when the generator changes; expansion profiles are additive, as described below.

Register an expansion-only profile by omitting dimensions:

~~~sh
supermem index add-profile \
  --profile-id query-expansion-v1 \
  --model-digest sha256:GENERATOR_CONFIGURATION_DIGEST
~~~

Register a dense profile with its exact dimensions:

~~~sh
supermem index add-profile \
  --profile-id local-encoder-384-v1 \
  --model-digest sha256:MODEL_AND_PREPROCESSING_DIGEST \
  --dimensions 384
~~~

Repeating an identical registration is safe. An existing profile cannot be updated with a different digest or dimension count.

Fetch current documents that need enrichment. Index administration uses one exact namespace, workspace, and repository scope; the usual `--cwd`, `--namespace`, `--workspace`, and `--repo-id` scope options apply.

~~~sh
supermem index pending \
  --profile-id query-expansion-v1 \
  --cwd . \
  --limit 100 > pending.json
~~~

`pending` emits a JSON array containing the current memory ID, revision, content hash, title, body, tags, entities, and artifacts. Feed that file to a local encoder, an external provider, or deterministic expansion rules outside super-mem. The worker should return a JSON array or JSONL records with the source identity unchanged:

~~~json
{
  "memory_id": "018f1000-0001-7000-8000-000000000001",
  "revision": 1,
  "content_hash": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "expansions": ["likely query wording", "related coding concept"]
}
~~~

A dense-profile record must also contain `"vector": [0.12, -0.03, ...]`. Its `expansions` array may be empty. Expansion-only profiles must not include a vector. Registration batches are limited to 256 records.

Register the completed batch in the same exact scope:

~~~sh
supermem index register \
  --profile-id query-expansion-v1 \
  --cwd . \
  projections.jsonl
~~~

Omit the input path, or use `-`, to read from standard input. Registration is atomic and idempotent for byte-identical records. Each record is a compare-and-swap against the current memory revision and content hash. If the memory changed while the worker was running, the batch is rejected instead of attaching stale generated data.

Check coverage with:

~~~sh
supermem index status --profile-id query-expansion-v1 --cwd .
~~~

The result reports eligible, indexed, pending, and stale counts. Run `pending` again until the intended scope is covered. A worker failure does not affect ordinary writes or default recall; it only leaves projections pending. All current expansion profiles contribute in stable profile order to an FTS field capped at 64 KiB per memory, so register only profiles that should influence recall in that database. There is currently no per-query expansion-profile selector or profile-removal CLI.

## Dense recall

Dense document vectors are optional and caller-supplied. Components must be finite, non-zero as a vector, and match the profile's dimension count, which may be from 1 through 4,096. super-mem stores canonical little-endian `f32` components, a deterministic 128-bit random-hyperplane signature, and a checked norm. Profiles also record the core signature-algorithm version so a future algorithm cannot silently reinterpret old projections as current.

The query must be encoded by the same profile. For the CLI, place the query vector in a JSON number array:

~~~sh
supermem recall \
  --query "why did the worker deadlock?" \
  --cwd . \
  --dense-profile local-encoder-384-v1 \
  --dense-vector-file query-vector.json \
  --dense-min-similarity 0.20
~~~

MCP `memory_context` exposes the equivalent `dense_profile`, `dense_vector`, and optional `dense_min_similarity` fields. Supplying a missing profile, a vector with the wrong dimensions, a zero or non-finite vector, or an invalid threshold returns an error. The default threshold is `0.0`, so anti-correlated vectors do not receive a dense retrieval signal. Without these fields, recall does not perform dense scoring.

Dense candidate selection is portable and bounded:

- With at most 4,096 eligible vectors, recall computes exact cosine similarity for every vector.
- Above 4,096, it streams the scoped 128-bit signatures into a bounded heap, selects 512 candidates by Hamming distance, then decodes and reranks that shortlist by exact cosine similarity. The signature is an angular prefilter, not the final score.

Scope and lifecycle eligibility are applied before either path. Final dense-channel ordering always uses exact cosine, but the larger path is approximate because a true neighbor can be omitted by the signature shortlist. This is a deliberate distribution and dependency tradeoff, not a claim of ANN-quality recall.

## Rebuilds and snapshots

Canonical events, memories, revisions, evidence, links, and feedback remain SQLite truth. FTS rows, alias-version markers, search profiles, expansions, vectors, and random-hyperplane signatures are derived search state.

Rebuild deterministic aliases and FTS from current canonical heads and any current registered projections with:

~~~sh
supermem index rebuild
~~~

Opening a database also detects missing or old alias projections and rebuilds them. `rebuild` does not call a model or create missing background projections.

JSONL snapshots intentionally exclude search profiles and projections. After importing a snapshot, register the desired profiles again and regenerate their pending projections. A raw filesystem backup of the SQLite database is different: it may contain this derived state.

## Privacy and integrity

Pending documents contain the stored, already-redacted memory fields, but they can still contain private source text and paths. Sending them, or recall queries, to an external encoder creates a separate disclosure boundary that super-mem cannot control. Embeddings can also retain information about their input. Prefer a local worker when that boundary is unacceptable, and never treat pattern-based redaction as a guarantee.

Registered expansion text is bounded, deduplicated, and passed through secret-pattern redaction again when the configured redaction pipeline is enabled (the default). The profile schema has no provider-credential or local-model-path field. Registration requires exact scope, current revision, and current content hash; generated text is never rendered in the context packet. These controls limit stale or cross-scope attachment, but a caller authorized for a scope can still register misleading expansions or vectors.

## Evaluation limits

The checked-in [`fixtures/retrieval`](../fixtures/retrieval/) corpus provides labeled coding-memory cases and safety assertions for exact identifiers, errors, paraphrases, repository/workspace isolation, Git applicability, and revisions. It is a small starter fixture, not a representative benchmark, and it does not establish a general quality or latency improvement.

Any evaluation of a generator should compare lexical-only recall, hybrid recall with an exact vector scan, and the random-hyperplane shortlist on the same held-out corpus. Report MRR, Recall@k, nDCG, forbidden-result count, exact-neighbor recall, latency, memory, and index size. Keep qrels out of indexed or encoded inputs, publish model and preprocessing digests, and do not tune on the cases reported as held out. See [Evaluation](evaluation.md) for the full protocol.
